# Mission

## Why I'm learning this

Working through Jon Bodner's *Learning Go* (O'Reilly) chapter by chapter, doing the
end-of-chapter exercises in `ch1/` … `chN/`. The goal is broad, durable fluency in
the language itself — not a single shipping project.

Because the exercises are the vehicle, lessons should be grounded in the code I
actually wrote for the current chapter, not in invented examples.

## What success looks like

- I can read a Go compiler error and know which language rule it is enforcing.
- I reach for the idiomatic Go shape first, instead of the shape my other
  languages would suggest.
- I finish the book's exercises without needing the answer key.

## How I like to learn

Code-first: show the mechanism in real code from my own files, then quiz me on
recall. I would rather be told "this is illegal, here is the exact compiler
message" than be given a rule in the abstract.
