Assertions, Switches &
Optional Behaviour

Getting a concrete type back out of an interface value, and using that to offer behaviour without demanding it.

01Three operations, often confused

OperationSyntaxCheckedOperand
ConversionT(x)compile timeany compatible type
Type assertionx.(T)run timeinterface value only
Type switchswitch v := x.(type)run timeinterface value only

"Cast" in Java or C# covers the first two at once. Go splits them because only one of them can fail.

02Forms

v, ok := x.(T)   // comma-ok: never panics, ok reports success
v := x.(T)       // naked: panics on mismatch

switch v := x.(type) {
case *League:          // v is *League
case RankerAdapter:    // v is RankerAdapter
case nil:              // x itself held nil
case A, B:             // v keeps x's interface type
default:               // v keeps x's interface type
}

03Optional-behaviour probe

// Accept the narrow interface; ask for more at runtime.
if sw, ok := w.(io.StringWriter); ok {
	return sw.WriteString(s)  // better path
}
return w.Write([]byte(s))     // always-works path

// Probing for a single method reads well inline:
if c, ok := r.(interface{ WinCount(string) int }); ok { … }

04Errors

fmt.Errorf("writing %v: %w", rank, err) // %w wraps; %v discards

var pe *fs.PathError
if errors.As(err, &pe) { … }   // finds it at any depth
if errors.Is(err, fs.ErrNotExist) { … } // compares to a sentinel

Hand-rolled err.(*T) inspects only the outermost error and misses anything wrapped. Use errors.As.

05When to use which

SituationReach for
Offering a faster path if availablecomma-ok assertion on an optional interface

Branching over concrete types you ownusually wrong — add a method instead
A mismatch means the program is brokennaked assertion; the panic text is precise

06Messages, decoded

MessageMeaning
