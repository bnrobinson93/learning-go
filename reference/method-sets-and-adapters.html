Method Sets & Adapters

The rules that decide whether a type implements an interface, and the three moves for making it implement one you do not control.

01The rules

RuleConsequence
Implementation is structural and exact. Same method name, same parameters, same results. No covariance: []TeamName ≠ []string.
Method set of T holds value-receiver methods; method set of *T holds both. If any required method has a pointer receiver, pass &v, not v.
Methods may be declared on any defined type in the same package. Including func types, slice types, and string types. This is what makes adapters possible.
A defined type declared from another type starts with an empty method set. type B A copies structure, not behaviour. Use embedding to keep methods.
Embedding promotes fields and methods; a method declared directly on the outer type shadows the promoted one. Reach the original explicitly: outer.Inner.Method().
Slice conversion needs identical element types. TeamName → string converts. []TeamName → []string does not. Copy in a loop.

02Adapter recipes

A. Wrapper by embedding — keeps the original's behaviour

type Wrapper struct {
	Original
}

func (w Wrapper) Want() []string {
	src := w.Original.Have() // shadowed? qualify it
	out := make([]string, 0, len(src))
	for _, v := range src {
		out = append(out, string(v))
	}
	return out
}

use(Wrapper{original})

B. Func adapter — one-method interfaces

type WantFunc func() []string

func (f WantFunc) Want() []string { return f() }

use(WantFunc(obj.SomeMethod))   // method value: receiver pre-bound
use(WantFunc(func() []string { … })) // or a literal

The standard-library instance of this is http.HandlerFunc.

C. Defined type over a non-struct — when you own only the data

type Names []TeamName

func (n Names) Want() []string { … }

03Decoding the error

cannot use league (variable of struct type League) as Ranker value
in argument to RankPrinter: League does not implement Ranker
(wrong type for method Ranking)
	have Ranking() []TeamName
	want Ranking() []string

wrong type for method means the name matched and the signature did not — you need an adapter, or a signature change. Contrast with missing method, which means the method is absent entirely, or is present only on the pointer's method set and you passed a value.

04Vocabulary

TermMeaning
Method setThe methods callable on a type; what interface satisfaction is checked against.
Defined typeA type created by a type X Y declaration. Distinct from Y, with its own (initially empty) method set.
Underlying typeThe structural type beneath a defined type; governs convertibility and literal assignment.
EmbeddingA field declared with no name, whose fields and methods are promoted to the outer type.
PromotionAn embedded type's method appearing in the outer type's method set.
ShadowingAn outer method at a shallower depth taking precedence over a promoted one of the same name.
Method valuev.M without call parentheses: a function value with the receiver already bound.
Method expressionT.M: a function taking the receiver as its first explicit argument.
AdapterA type that wraps another and presents the method set some interface requires.
