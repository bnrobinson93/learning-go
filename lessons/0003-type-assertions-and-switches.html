Type Assertions and Switches

You asked whether a Go conversion is "basically a cast." Here is the other half of that answer — the runtime-checked operation Go deliberately gave separate syntax. You have been calling a function that uses it all along.

01The distinction, finally complete

ConversionType assertion
SyntaxT(x)x.(T)
CheckedCompile timeRun time
OperandAny compatible typeAn interface value only
Can fail at runtimeNeverPanics, unless comma-ok
Asks"Reshape this into a T.""What is actually in this box?"

The operand restriction is worth internalising. An assertion unwraps an interface value to find the concrete type stored inside it — so there must be an interface value:

func bad(l *League) { _ = l.(Ranker) }

invalid operation: l (variable of type *League) is not an interface

02Comma-ok, and the naked form

if l, ok := r.(*League); ok {
	// l is a *League here
}
l := r.(*League) // panics if r holds anything else

panic: interface conversion: main.Ranker is main.RankerAdapter, not *main.League

Default posture

Use comma-ok. Reach for the naked form only where a failure is a genuine programmer error you want to crash on — and note that the panic message is excellent, so it is not an unreasonable choice in a program's own internals.

03The pattern that matters: optional behaviour

Here is the payoff, and it has been in your code since exercise 3. Your RankPrinter calls io.WriteString. That function is, essentially, this:

func WriteString(w Writer, s string) (n int, err error) {
	if sw, ok := w.(StringWriter); ok {
		return sw.WriteString(s) // fast path: no allocation
	}
	return w.Write([]byte(s))    // fallback: convert to []byte
}

Paraphrase of io.WriteString.

It accepts the narrow interface, then asks at runtime whether the concrete value happens to support something better. Callers that can, get the fast path; callers that cannot, still work. Checked:

os.Stdout        is io.StringWriter: true
*bytes.Buffer    is io.StringWriter: true
*strings.Builder is io.StringWriter: true

So your RankPrinter(…, os.Stdout) has been taking the allocation-free path this whole time, because of an assertion you never wrote.

The same probe, in your own code

You can ask whether a Ranker can do more than rank — using an anonymous interface written inline, which is the idiomatic way to probe for one method:

func RankPrinter(r Ranker, w io.Writer) error {
	counter, hasCounts := r.(interface{ WinCount(string) int })

	for _, rank := range r.Ranking() {
		line := rank
		if hasCounts {
			line = fmt.Sprintf("%s (%d)", rank, counter.WinCount(rank))
		}
		if _, err := io.WriteString(w, line+"\n"); err != nil {
			return fmt.Errorf("unable to write %v: %w", rank, err)
		}
	}
	return nil
}

Give *League a WinCount method and it prints counts. Pass your RankerAdapter — which has no such method — and it silently prints plain names. Neither Ranker nor League had to change.

04Type switches

When you need to branch across several concrete types, the switch form binds the variable per-case:

switch t := v.(type) {
case *League:
	fmt.Println("a league with", len(t.Wins), "teams") // t is *League
case RankerAdapter:
	fmt.Println("a func adapter")                      // t is RankerAdapter
default:
	fmt.Println("something else")                      // t is Ranker
}

In default — and in any case listing two or more types — t keeps the original interface type, because there is no single concrete type to give it.

Smell

A type switch over concrete types that you own is usually an interface you failed to define. Prefer adding a method. Type switches earn their place for handling values you do not control — any from decoded JSON, sentinel error types, or optional-behaviour probes like the one above.

05The one you will actually use most

Error handling is assertion-shaped, but do not write the assertion by hand — wrapped errors hide inside other errors, and errors.As walks the chain for you:

if pe, ok := err.(*fs.PathError); ok { … } // misses wrapped errors
var pe *fs.PathError
if errors.As(err, &pe) { … }              // unwraps as it searches

Note that your RankPrinter currently builds its error with fmt.Errorf("unable to write %v", rank) — which discards the underlying err entirely. Use %w to wrap it, so callers can errors.As their way back to the real cause. (errors.As)

06Check yourself

What does x.(T) require of x?

Assertions unwrap interface values. On a concrete type the compiler rejects it: invalid operation: … is not an interface.

Why does io.WriteString assert for io.StringWriter rather than just requiring it?

Accept the narrow interface, then probe for the better one. Callers that support it get the allocation-free path; the rest fall back to Write([]byte(s)).

In a type switch, what type does the bound variable have in default?

Only a single-type case can narrow it. In default, or in a case listing several types, the variable keeps the original interface type.

Why prefer errors.As over asserting on the error directly?

A direct assertion only inspects the outermost error, so it misses anything wrapped with %w. errors.As walks the whole chain.
